## Правила, що часто забуваються
- Відповідай українською, просто, про себе в чоловічому роді. Звук гри в моїх тестах ВИМКНЕНИЙ (`setAudioMuted(true)` у кожному новому Electron-скрипті). Користувачку звати за потреби в жіночому роді («скопіювала»): вона просила «в чоловічому роді» лише про мене.
- Візуальні новинки спершу показуй зразками (листи A/B/C), після вибору вставляй. Публікуй лише після «публікуй»/«онови на сайті»; exe лише після «зроби на пк»/«онови на пк». Автоматичний режим блокує `git push`, поки в чаті нема явного слова користувачки.
- Випуск вручну: скрипт на кшталт `release_r40.sh` (sync → autotest `--quick` → `node tools/publish.js` → `cd desktop; node prepare.js; npx electron-builder --win portable --config.electronDist=node_modules/electron/dist --config.electronVersion=33.4.11` → копія на стіл → `CAPY_NOGOD=1 node desktop/prepare.js` → `git add` конкретних шляхів → коміт з трейлером → `git push` → `bash tools/watch-pages.sh 9 <слово>`). НЕ використовуй `rm -f dir/*` з глобом: безпекова перевірка блокує (давай точні імена файлів). Не клади в git `backups/` і `previews/` (`git add` лише з явними шляхами).
- Перед змінами копія `game.html` у `backups/`; після кожної задачі пункт у `PROGRESS.md`.
- Правки: у `src/*.js` напряму (потім `node tools/build.js`) або скриптом-латкою (приклади `previews/r40/patch*.js`: читають файл, `includes(old)` → `replace` → записують; `python3` тут заглушка Windows Store — НЕ використовувати, тільки node). НЕ вести два чати одночасно в цій папці.
- Перевірка перед випуском: `bash tools/autotest.sh --quick` (ПК + 390×844, ~2 хв). Знімки сцен для перевірки: сценарії для `previews/video/rec.js` (`prepState`, `scene(ep, lvl, phase)`, `grow`, `cap`, `flash` у `scn_common.js`), потім кадр `ffmpeg -ss T -i file.mp4 -frames:v 1 out.png`.
- `lineG` (Брезенхем) зависає на дробових координатах: завжди округляй.
- Перегляд епохи без модалки: `state.epoch=N; state.seasonsIntro=1` (інакше з 2-ї епохи вилазить вікно «Пори року»).
